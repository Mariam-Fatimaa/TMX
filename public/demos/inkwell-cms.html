01 — Content modelling

Model your content the way your desk thinks about it.

Define articles, authors, recipes or live blogs as typed models with references, validation and reusable blocks. No developer needed for a new field.

  • Headline *text · max 90
  • Standfirsttext · max 240
  • Bodyrich text · blocks
  • Author *ref → Author[]
  • Sectionenum
  • Hero imageasset · alt required
  • Embargo untildatetime · tz
model Article {
  headline   Text     @required @max(90)
  standfirst Text     @max(240)
  body       RichText @blocks(quote, image, embed)
  authors    Author[] @required
  section    Section
  hero       Asset    @alt
  embargo    DateTime @timezone
}
  • Full name *text
  • Bylinetext · max 40
  • Short biorich text · 280
  • Portraitasset · 1:1 crop
  • Deskenum
  • Socialsurl[]
model Author {
  name     Text     @required
  byline   Text     @max(40)
  bio      RichText @max(280)
  portrait Asset    @crop(1:1)
  desk     Desk
  socials  Url[]
}
  • Title *text
  • Servesnumber · 1–24
  • Ingredientslist → Ingredient

model Recipe {
  title       Text         @required

03 — For developers

Typed content, any framework, at the edge.

REST and GraphQL APIs served from 280 edge locations, a typed SDK generated from your models, and webhooks for everything else.

import { inkwell } from "@inkwell/next";

export const revalidate = 60; // or revalidate on publish via webhook

export default async function Story({ params }) {
  const { slug } = await params;
  const story = await inkwell.article.get({ slug, include: ["authors"] });

  return (
    <article>
      <h1>{story.headline}</h1>
      <Byline authors={story.authors} />
      <RichText value={story.body} />
    </article>
  );
}
